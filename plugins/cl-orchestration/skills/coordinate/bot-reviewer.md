# Reviewer bot run

The procedure of one reviewer bot run: a first review, a re-review of one round, or the verify pass of a sensitive change's first round, as the prompt says. [SOUL.md](SOUL.md) holds first. The prompt holds the reviewer's brief of [Review](review.md#review): pull request `<n>` of `<owner/repo>`, `<head>`, the range, the level, whether the security pass runs, the Thread block, the default branch's `AGENTS.md`, the worker's claims and the threads file. Then the result file.

1. **Clone.** Clone the repository into a new folder `<bot home>/clones/<repo>-<n>-<counter>` of this bot's home, the next free counter, as [Scratch clone](scratch-clone.md) says: `gh repo clone` with `--no-upstream -- --filter=blob:none --no-checkout`, `rev-parse --git-dir` prints `.git`, `fetch` exits 0. `git -C <clone> cat-file -e <head>^{commit}` must pass, else the report says the head is gone and the run ends.
2. **Read** only through git, with every limit of that section: no checkout, no file of the pull request on disk, a path only inside single quotes, nothing of the pull request runs. A permission dialog or a refused git command: answer nothing, report it, end.
3. **Review** at the prompt's level, as [The commands](review.md#the-commands) says: `/code-review <level>` on the range in the clone, and the security pass yourself where the prompt asks for it. A re-review reads what [Rounds](review.md#rounds) names (the diff since the reviewed head, or the remerge diff) and the earlier findings. A verify pass marks each Blocking and Important finding confirmed or disputed, with evidence.
4. **Threads.** For each thread of the threads file: fixed at `<head>`, no finding, or a finding.
5. **Report** in the result file, with the file tool: the review of record lines of [Review of record](review.md#review-of-record) (head, round, kind, level, model, security pass, verdict and counts), then each finding with severity, file, line, the thread id it covers and what fixes it, and the threads of step 4. A review that could not cover its scope (a compaction, a read that failed, a part left out) says `void` and why. The worker's claims are claims: verify them, never cite them as evidence.
6. Delete the clone, a command of its own with the folder's literal absolute path, and end.

This run posts nothing on GitHub and edits no file but its clone: the project bot posts the review of record and acts on the verdict.
