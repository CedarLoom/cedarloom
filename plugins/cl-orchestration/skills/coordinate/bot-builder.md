# Builder bot run

The procedure of one builder bot run, one of three kinds as the prompt says. [SOUL.md](SOUL.md) holds first. After the prompt's text, it names the result file.
- **Build:** one issue, from the spec in the prompt ([spec-template.md](spec-template.md)), whose Depth, Risk, owned paths, Thread block and handoff block hold.
- **Plan:** a build's spec after the line `Plan only.`: the plan of a deep issue or one that leaves its approach open, and nothing else.
- **Fix:** one round's findings, a red head or a conflict of one pull request. The prompt holds the follow-up: `<owner/repo>`, `<n>`, `<branch>`, `<default branch>`, `<head>`, the issue's Thread block and acceptance criteria, then the findings in the project bot's words (severity, file, line, thread id), the red checks or the conflict, and the threads file.

1. **Clone.** `gh repo clone <owner/repo> <bot home>/clones/<repo>-<n>-<counter> --no-upstream` into a new folder of this bot's home, the next free counter; `git -C <clone> rev-parse --git-dir` prints `.git`. A plan stays on the default branch. Otherwise `git -C <clone> switch <branch>` where `origin/<branch>` exists (an earlier run's work, and always for a fix), else `git -C <clone> switch -c <branch> refs/remotes/origin/<default branch>`, the branch of the spec. A fix: `git -C <clone> rev-parse HEAD` must print `<head>`: another head means the branch moved, so report that and end. Work only in that clone.
2. **Work.**
   - Build the issue as the spec says, with the workflow skill at the spec's depth, which plans inline: only the owned paths, the gates of `AGENTS.md`, a test only where its test rule asks for one.
   - Plan the issue at the spec's depth as the `plan` agent of the cl-workflow plugin says: read only, no edit, commit or push. A choice the spec, the code or the docs do not settle goes into its open questions with your recommendation.
   - Fix: check each finding on the branch. Fix the confirmed ones; for one that does not hold, keep the evidence (file and line, a command and its output). A red check: read its log (`gh run view <run id> -R <owner/repo> --log-failed`) and fix the cause, never the check. A conflict: `git -C <clone> merge refs/remotes/origin/<default branch>` after a fetch, resolved the way the repository's conventions say. Stay within the issue's scope; a finding that needs more goes in the report. Then run the checks `AGENTS.md` names for the changed area; a failing one is fixed or reported, never skipped.
3. **Questions.** Answer what the spec, the code or the repository's docs settle, and name the source. Any other choice that is safe and reversible takes the recommended default, named in the report. An owner-only choice ([SOUL.md](SOUL.md#owner-only-decisions)) ends the run as BLOCKED with the question and your recommendation, after step 4 for the edits made so far: this run is never resumed, and the next one starts from the pushed branch.
4. **Commit and push**, never for a plan, on `<branch>`, the message from a file. A build: before the push, every path that `git -C <clone> diff --no-renames --ignore-submodules=none --name-only refs/remotes/origin/<default branch>...HEAD` or `git -C <clone> log --format= --name-only --cc --no-renames --ignore-submodules=none --no-show-signature refs/remotes/origin/<default branch>..HEAD` lists counts, as [Commit and push](modes.md#commit-and-push) says for a supervised worker: a path outside the owned paths or under `.github/` pushes nothing and ends the run as BLOCKED, as step 2 of [Commit and push](modes.md#commit-and-push) says. A fix: one fix commit. Then `git -C <clone> push origin <branch>`, never with force; a rejected push is reported, not retried with force. No pull request: the project bot opens the draft, and the spec's lines to open or update one, wait for its checks or reply to review threads do not hold for this run. A permission dialog or a refused command: answer nothing, report it, end.
5. **Report** in the result file, with the file tool:
   - A build, as the spec's handoff block asks: the outcome, the branch and its head commit, a pull request title and body, the gate commands and their results, the defaults taken, and what was not checked.
   - A plan: the plan, the commit it read and what was not checked.
   - A fix: DONE or BLOCKED, the fix commit, per finding and per thread of the threads file the fix commit or the evidence, the gate commands and their results, and what was not checked. A question goes in the report as BLOCKED, with your recommendation: the next round starts a new run.
6. Delete the clone, a command of its own with the folder's literal absolute path, and end.

This run posts nothing on GitHub but its push: the project bot opens the draft, replies on the threads and starts the re-review. Before it opens the draft, the project bot takes a new clone under `<bot home>/clones/` as [Scratch clone](review-and-merge.md#scratch-clone) says and runs the two commands of step 4 there, `refs/remotes/origin/<branch>` in place of `HEAD`, `<branch>` from the spec: a path outside the owned paths or under `.github/` makes the item BLOCKED for the owner, as step 2 of [Commit and push](modes.md#commit-and-push) says. The push has run by then, so this check stops the draft and nothing earlier.
