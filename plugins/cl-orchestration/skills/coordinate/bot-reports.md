# Bot run reports

How a project bot run takes the report of a role bot run or an Orca worker, in the pick sweep and in catch-up condition 7. Names and steps are those of [bot-project.md](bot-project.md). Each result goes into its entry's `result` in `runs` or `dispatches`.

- **A build's first report with a pushed branch.** A builder bot's: check its files as [bot-builder.md](bot-builder.md) ends, write `{ "title", "head", "base", "body", "draft": true }` (body: step 3 of [Commit and push](commit-and-push.md)) to `pr.json` in the run folder, then `gh api repos/<owner/repo>/pulls -X POST --input <its path>`. An Orca worker's: `node <skill folder>/commit-push.mjs commit` for an automatic worker, `commit-push.mjs supervised` for a supervised Claude Code one. Then `pr-<n>.json` (repo, pr, issue, branch, project, round 1, the run) and event rules `<owner/repo>#<n> ci_passed` on `github.ci_passed subject=<owner/repo>#<n>`, alike for `ci_failed` and `pr_conflicted`, each `--runs-in new --results-to chat` naming `bot-project.md`.
- A review whose Head line names another head than its entry's: a new review of the entry's. Without Head line or verdict it starts nothing; where the head is still the entry's, the review is the owner's ([Review](review.md#review)), filed once as `held` (`no review of <head>`). Else it is the [review of record](review.md#review-of-record), recording `reviewedHead`, `reviewUrl` and `round`: findings go to a fix run ([Rounds](review.md#rounds)), `void` to a new review, none Blocking or Important on as a green accepted head ([Pull request events](bot-project.md#pull-request-events)).
- A fix report: reply on each thread it names with its commit or evidence, from a file, through the `pre-merge.json` command. A builder's question is answered from written sources, named; an owner-only one is filed as an approval, its answer going to a new run.
- **Plan report.** `git -C <clone> ls-remote --exit-code --heads origin <spec branch>`: any exit but 2 (absent), even 128, makes the item BLOCKED for the owner and starts no build. Then its questions as a build's, an owner one with an Issue line ([Labels and title](approvals.md#labels-and-title)), and `cl:in-progress` off.
- A maintain run's report: [Maintenance](bot-upkeep.md#maintenance) step 2.
- A finished Orca worker: [Clean up](orca-clean-up.md). A clone a role bot run's report names as left goes with the pull request's.
