# Draft first

Not under an orchestration spec, whose flow applies.

1. After settling and the plan check, build and run the thinnest working end-to-end slice, then open a draft pull request with a preview link or screenshots.
2. The user looks; an unattended run skips this.
3. One round finishes the change with the feedback and the polish, through the depth's checks.
4. The depth's review runs before the draft is marked ready; a draft never merges without it.

A throwaway prototype that answers a design question stays out of the repository ([research.md](research.md)).
